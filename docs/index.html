Vitra CSS

Premium glassmorphism, directional particles, ambient scenery and smooth motion — CSS-only core, optional JS, zero dependencies.

v1.14.2 CSS-only core 0 dependencies

Introduction

Vitra is a lightweight, zero-dependency CSS framework built around glassmorphism, directional particles, ambient scenery, and smooth motion. The core is pure CSS: themes, glass surfaces, layout, components, and utilities all work from a single stylesheet.

The stylesheet is 18.9 kB brotli. JavaScript is optional and progressive: a 7.5 kB (brotli) script adds interactive behavior — theme persistence, modals, drawers, tooltips, toasts, dropdowns, particles — but nothing in the CSS depends on it. If the script never loads, every component still renders and the page stays usable.

This page is built with Vitra itself: the glass header and sidebar, the badges, the tabs below, the drawer behind the menu button on a phone, the toast you'll see when you copy a snippet. Switch the theme from the header dropdown and the whole page re-colors. For a full visual tour, see the interactive demo.

Installation

Add the stylesheet to <head>:

<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/DesvoSoft/Vitra@v1.14.2/dist/vitra.min.css" integrity="sha256-2OyRLn3Y5YKEEEfm8Ag2Xw6t1Iecy/yj7wif5LoDKyQ=" crossorigin="anonymous">

Optionally add the script before </body> — it enables modals, tooltips, toasts, dropdowns, particles, and theme persistence:

<script src="https://cdn.jsdelivr.net/gh/DesvoSoft/Vitra@v1.14.2/dist/vitra.min.js" integrity="sha256-XfDZdHFCtz3eXkyZ82L9abRDbp+yhwDFOvvsWNpqjFw=" crossorigin="anonymous" defer></script>

Always pin a version tag (@v1.14.2). The integrity hash makes the browser refuse the file if it ever differs from the release; the hashes of every distributed file are in dist/SRI.txt on the tag.

Vitra is not published on the npm registry: install it from GitHub, pinned to a tag. A registry package named vitra-css is not this project.

npm install github:DesvoSoft/Vitra#v1.14.2

Then import the stylesheet and, if you need interactivity, the modules by name:

import 'vitra-css/dist/vitra.min.css';
import { theme, drawer } from 'vitra-css';

The package ships the CSS bundle and its three pieces, the script-tag build (dist/vitra.js), an ES module with named exports (dist/vitra.esm.js), a CommonJS build (dist/vitra.cjs) and TypeScript definitions.

Which file do I need?

FileUse
vitra.min.cssEverything visual (18.9 kB brotli). Required.
vitra.core.min.css, vitra.scenery.min.css, vitra.effects.min.cssThe same rules in three pieces, to leave out the scenery or the effects. scenery and effects need core; loading all three costs more than the bundle.
vitra.min.jsInteractive components and theme persistence (7.5 kB brotli). Optional.
vitra.esm.js / vitra.cjsThe same modules for bundlers, as named exports. Importing runs the auto-init, so the package is not side-effect free and is not tree-shaken.

Theming

Themes are applied with a single attribute on the root element. Every --vitra-* token — accent hue, backgrounds, surfaces, borders, text — updates instantly.

<html data-theme="dark">

Built-in themes

Seven presets, each with its own accent hue and tinted neutrals so every surface carries a trace of the accent:

light dark auto pastel neon ocean emerald

auto follows the operating system's prefers-color-scheme and re-resolves live when it changes.

Persistence

With the optional script, initialize once and the visitor's choice is stored in localStorage and restored on every page that calls init:

Vitra.theme.init({ defaultTheme: 'auto', persist: true });

This docs page and the demo share that stored choice — pick a theme here and the demo opens in it.

Creating a custom theme

A theme is a [data-theme] block that overrides tokens. Start from the accent and the base surfaces:

html[data-theme="sunset"] {
  --vitra-color-accent-h: 18;
  --vitra-color-accent-s: 85%;
  --vitra-color-accent-l: 58%;
  --vitra-color-bg: hsl(18deg 30% 8%);
  --vitra-color-surface: hsl(18deg 40% 90% / 6%);
  --vitra-color-surface-hover: hsl(18deg 40% 90% / 10%);
  --vitra-color-border: hsl(18deg 40% 90% / 12%);
  --vitra-color-text-primary: hsl(18deg 20% 95%);
  --vitra-color-text-secondary: hsl(18deg 15% 72%);
}

Set it with data-theme="sunset" directly. Note that Vitra.theme.set() only accepts the built-in names — apply custom themes via the attribute, or keep managing them yourself.

Tabs CSS + your script

Tab styling is CSS. The markup carries the roles and states; switching panels is a few lines of your own (this page's switcher, with arrow keys, drives the Installation section above). There is no Vitra.tabs module in 1.14.

<div class="vitra-tabs" role="tablist" aria-label="Sections">
  <button class="vitra-tabs-tab" role="tab" id="tab-1" aria-selected="true" aria-controls="panel-1">One</button>
  <button class="vitra-tabs-tab" role="tab" id="tab-2" aria-selected="false" aria-controls="panel-2">Two</button>
</div>
<div class="vitra-tabs-panel vitra-active" role="tabpanel" id="panel-1" aria-labelledby="tab-1">First panel</div>
<div class="vitra-tabs-panel" role="tabpanel" id="panel-2" aria-labelledby="tab-2">Second panel</div>

The selected tab is styled by aria-selected="true"; a panel shows only while it has .vitra-active. Your click handler updates both.

Scenery & Motion

An ambient mountain landscape for heroes and full-page backdrops, plus the motion tokens the components use. Everything here animates transform and opacity only, so it runs on the compositor: an idle page with the scene running does no repaints, and it pauses while offscreen.

Scenery CSS-only

With vitra.js on the page, one empty element is enough — the eight layers are written for you:

<!-- Full-page backdrop -->
<div class="vitra-scenery"></div>

<!-- Or inside a hero -->
<section style="position: relative;">
  <div class="vitra-scenery-inline" data-vitra-moon="crescent"></div>
  <div class="vitra-glass" style="position: relative;">Content</div>
</section>

Without JavaScript, write the layers yourself. The scene is pure CSS either way:

<div class="vitra-scenery" aria-hidden="true">
  <div class="vitra-scenery-sky"></div>
  <div class="vitra-scenery-stars"></div>
  <div class="vitra-scenery-clouds"></div>
  <div class="vitra-scenery-halo"></div>
  <div class="vitra-scenery-ridge-far"></div>
  <div class="vitra-scenery-ridge-mid"></div>
  <div class="vitra-scenery-ridge-near"></div>
  <div class="vitra-scenery-grain"></div>
</div>
TokenDefaultDoes
--vitra-scenery-intro1Entrance length multiplier. 0 = the scene is simply there.
--vitra-scenery-depth1Scroll parallax strength for .vitra-scenery-inline. 0 = locked.
--vitra-scenery-speed1Drift speed multiplier.
--vitra-scenery-halo-x / -y / -size76% / 13% / clamp(56px, 9vmin, 110px)Moon (or sun, on light themes) position and size.
--vitra-scenery-hue / -sattheme accentBase colour of the whole scene.

Scroll depth needs a host that is not overflow: hidden. That makes the host the scroll container the effect listens to, and it silently stays off. Use overflow: clip, or nothing — the scenery root clips itself. The same goes for overflow-x: hidden on both html and body.

Spring easing CSS-only

Modals, toasts, drawers and dropdown menus spring in and ease out. The same tokens are yours to use — put the spring on the open state only:

.my-panel.open {
  transition: transform var(--vitra-duration-spring) var(--vitra-ease-spring-soft);
}

--vitra-ease-spring overshoots and settles; --vitra-ease-spring-soft barely overshoots. Both are sampled damped springs via linear(), with a cubic-bezier fallback.

Animated theme change needs JS

Opt in and the new theme grows as a circle out of the control that was pressed. Try the theme menu at the top of this page.

button.addEventListener('click', (event) => {
  Vitra.theme.toggle({ transition: true, origin: event });
});

It uses the View Transitions API: browsers without it, and visitors who prefer reduced motion, get the instant swap.

A Vitra modal

Focus is trapped, Esc closes, body scroll is locked.

JavaScript API

The script exposes a single global, Vitra, with one submodule per feature. The ES module build exports the same modules by name (import { theme, drawer } from 'vitra-css'); importing it runs the auto-init, so it is not side-effect free. Every module is optional — use only what you call.

Vitra.theme

MethodDoes
get()Current theme name ('auto' if unset).
set(name, options?)Applies a built-in theme; returns false and warns on unknown names. { transition: true, origin } animates the swap — origin is a pointer event, an element or { x, y }.
toggle(options?)Switches light ↔ dark (resolves auto first); returns the new theme. Takes the same options as set().
init(options)Restores stored choice; { defaultTheme: 'auto', persist: true, transition: false }. transition: true animates every later change.
getEffective()Resolves auto to 'light' or 'dark'.
getValidThemes()Array of the seven built-in names.
clear()Removes the stored preference.

Vitra.particles

Vitra.particles.spawn(10, {
  container: 'body',
  size: 4,
  direction: 'down'   // 'down' | 'down-left' | 'down-right' | angle in degrees | omit for ambient bob
});
Vitra.particles.destroy();   // all, or destroy(n)
Vitra.particles.limits();    // { active, available, max }

Hard caps: 40 particles on desktop, 15 on mobile. spawn beyond the cap is ignored with a console warning.

Vitra.reveal

Vitra.reveal.init({
  selector: '.vitra-reveal',
  threshold: 0.1,
  rootMargin: '0px 0px 10% 0px',
  stagger: 100
});

Also count() (revealed so far) and reset() (re-arm everything). With prefers-reduced-motion, elements reveal immediately.

Vitra.modal

Vitra.modal.open('my-modal', { closeOnOverlay: true, closeOnEsc: true });
Vitra.modal.close();

open accepts an id, a selector, or an element. Any child with data-vitra-modal-close closes it.

Vitra.tooltip

Vitra.tooltip.show('#save-btn', 'Saves your draft', { position: 'top' });
Vitra.tooltip.hide();
Vitra.tooltip.init();   // activates all [data-vitra-tooltip] elements

Vitra.toast

Vitra.toast.show('Saved successfully!', { type: 'success', duration: 3000 });

Types: success, error, info, warning. closable: true adds a close button; duration: 0 keeps the toast until it is closed and always adds one. The container is a polite live region and error toasts are alerts. Messages are rendered as text, never HTML.

Vitra.drawer

Vitra.drawer.open('#menu');
Vitra.drawer.close();
Vitra.drawer.toggle('#menu');   // true when it ends up open

Toggles are bound automatically from [data-vitra-drawer-toggle] (see Drawer). Only one drawer is open at a time.

Vitra.dropdown / Vitra.ripple / Vitra.spotlight

Behavior modules with init() / destroy(). They initialize automatically (see data-config): dropdowns from [data-vitra-dropdown-toggle], ripple from .vitra-ripple elements, spotlight cursor-tracking from .vitra-spotlight. Dropdowns work from the keyboard: ↓ on the toggle opens the menu, the arrow keys, Home and End move between items, Esc closes it.

Vitra.scenery

MethodDoes
init()Fills every empty .vitra-scenery / .vitra-scenery-inline root with its eight layers; returns how many. Runs automatically.
mount(target, options?)Turns any element into a scene. { inline: true, moon: 'crescent' }. Roots that already have layers are left alone.
destroy()Removes only the layers it injected.

Vitra.motionGuard

init() / observe(el) / destroy(). Pauses ambient loops — scenery, glow orbs, aurora, mesh gradient, gradient text, particles, spinners, skeletons, animated progress bars — while they are outside the viewport. Initializes automatically; skipped under reduced motion, where those animations are already off. It does not watch the DOM: call observe(el) for an element you add later.

Vitra.destroyAll()

Tears down every module — removes all listeners and injected nodes. Useful in SPAs on route teardown.

data-config

Declarative initialization without writing a line of JS: put a JSON data-config attribute on any element (conventionally <body>) and Vitra parses it on DOMContentLoaded.

<body data-config='{
  "theme": { "default": "auto", "persist": true },
  "reveal": { "stagger": 100 },
  "particles": { "count": 12, "direction": "down" },
  "dropdown": false
}'>

Defaults

ripple, toast, tooltip, drawer, dropdown, spotlight, scenery and motionGuard initialize by default — with or without a data-config element. Setting a module to false opts out. theme, particles, and reveal are opt-in: they only run when their key is present.

KeyDefaultValue
themeoffTheme name, or init() options object.
particlesofftrue, or spawn() options with count.
revealofftrue, or init() options object.
rippleonfalse to disable.
toastonfalse to skip creating the live region on load.
tooltiponfalse to disable.
draweronfalse to disable.
dropdownonfalse to disable.
spotlightonfalse to disable.
sceneryonfalse to stop empty scenery roots being filled.
motionGuardonfalse to keep ambient animations running offscreen.

Malformed JSON logs a [Vitra] console warning and falls back to the defaults above — it never throws. Each module starts on its own, so one that fails is reported and the next ones still run.

Accessibility & Browser Support

Reduced motion

Every animation layer — particles, scenery, reveals, cinematic effects — ships inside @media (prefers-reduced-motion: reduce) guards. When the OS setting is on, ambient motion stops and reveal elements appear immediately. No configuration needed.

Graceful degradation

  • backdrop-filter (glass) is wrapped in @supports — unsupported browsers get a solid translucent surface instead.
  • Modern features (oklch(), Popover API, @starting-style, container queries) all carry fallbacks; nothing breaks below Tier 1.
  • Without JavaScript, all styling works; modals, toasts, dropdowns, and theme persistence simply don't activate.

Keyboard & screen readers

Modals and drawers trap focus and restore it on close; a closed drawer is inert. Dropdowns work with the arrow keys and close on Escape, back to their toggle. One Esc closes one layer: a tooltip, then a menu, then the modal or drawer around it. Theme changes are announced via an aria-live region; tooltips add to aria-describedby. Every component reaches 4.5:1 text contrast and 3:1 control borders in all seven themes, and controls are 44 px tall on touch screens.
